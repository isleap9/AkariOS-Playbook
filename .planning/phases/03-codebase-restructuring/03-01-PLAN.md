### Risk Mitigation

- **Build script preserves exact content:** The split and rebuild process must produce byte-identical output to the original custom.yml (except for the line 24 fix), verified via `diff`
- **Backup:** `custom.yml.bak` created before regeneration
- **Section ordering:** Build script uses zero-padded filenames (01, 02, ... 40) for deterministic ordering
- **Validation:** Build script checks for `actions:` key and all 40 section headers in output

### Trade-offs Accepted

- User must run `python scripts/build-playbook.py` after editing any section file before loading in AME Wizard
- Git diffs will show section file changes instead of custom.yml changes (better granularity)
- AME Wizard still receives a monolithic file at runtime (unchanged)
- Additional tooling to maintain (build script)

### Non-Goals (Explicitly Out of Scope)

- Pre-compressed binary or minified output
- Any changes to playbook.conf or Executables/ or Images/
- CI/CD integration (this is a manual workflow project)
- Versioning the build output separately from source
